    Why each restock buys what it buys

    The rules, as the code has them

    1. Leaving the CX. The ship loads one bill: days of supply needed × daily use + 1 for buffer. Supply days default to the lap length, so a 3-day loop carries and an 8-day loop carries .
    2. At the base. It always leaves exactly one bill. Any excess inputs ride home, along with the base's outputs.
    3. Back at the CX. Unload-all puts the leftovers and outputs into the warehouse before the next load. So after the first lap, each departure only really costs what the base used since the last one.
    4. Restock target. The number of lap departures over the restock period (5 days in this example) times the bill of supply for the route.
    5. CX Buy buys the target minus what the warehouse already holds. It fills to the target, so overlapping windows never double-buy.
