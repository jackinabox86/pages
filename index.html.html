    Why each restock buys what it buys

    The rules, as the code has them

    1. Leaving the CX. The ship unloads everything it carries, refuels, then loads one bill: ceil(supply days × daily use + 1). Supply days default to the lap length, so a 3-day loop carries and an 8-day loop carries .
    2. At the base. It drops the bill, sweeps up every unit of that input on the base, then drops exactly one bill back. The base always ends the visit holding one bill. What was left over from last time rides home, along with the base's outputs.
    3. Back at the CX. Unload-all puts the leftovers and outputs into the warehouse before the next load. So after the first lap, each departure only really costs what the base used since the last one.
    4. Restock target. The larger of two numbers, per material:
      • Period amount. Lap ≤ 5 days: base use over 5 days, plus fuel for ceil(5 ÷ lap) laps, plus one working set if no ship is out yet. Lap > 5 days: the working set if no ship is out yet, otherwise nothing.
      • Departures in the next 5 days. The first departure of a route with no ship out takes the full working set. Every later one takes the base's use since the previous departure, +1. Fuel draws are planned at ×1.1.
    5. CX Buy buys the target minus what the warehouse already holds. It fills to the target, so overlapping windows never double-buy.
    Illustration values: the base uses 10 SUP/day and makes 6 PROD/day; the ship burns 4 SF per day of flight; the base starts with half a lap of supplies plus the +1. Legs are drawn at their nominal length. The extension estimates departures at 85% of leg time, so in a real route a 5-day window can catch a departure slightly earlier than drawn here.
